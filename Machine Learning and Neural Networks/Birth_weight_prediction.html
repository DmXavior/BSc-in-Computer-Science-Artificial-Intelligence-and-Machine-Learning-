Birth Weight Prediction¶

1. Problem Definition¶

This project aims to develop a predictive model for estimating a newborn’s birth weight (BWEIGHT) using prenatal data. The dataset consists of birth records with 36 predictor variables related to the mother, baby, and pregnancy. These features include maternal age, health metrics, prenatal visit history, baby’s gender, and other relevant factors recorded before birth.

Since birth weight is a continuous numerical variable (measured in pounds), this is a regression problem rather than a classification task. The goal is to accurately predict BWEIGHT based on available prenatal features.

Why is this important?

Accurate birth weight prediction can provide early warnings for low birth weight cases (under 5.5 lbs) or unusually large babies, both of which pose health risks. This information can be crucial for prenatal care, allowing healthcare providers to:

  • Identify high-risk pregnancies early,
  • Allocate medical resources effectively, and
  • Guide clinical decision-making for newborn care.

Thus, the primary motivation for this study is to explore whether we can develop a model that reliably estimates BWEIGHT using prenatal data, ultimately contributing to better maternal and infant healthcare outcomes.

2. Choosing a Measure of Success¶

Since this is a regression problem, we need appropriate evaluation metrics to quantify the prediction error and assess model performance. We will use the following three key metrics:

1. Mean Squared Error (MSE)

  • MSE is the average of the squared differences between the predicted and actual birth weights.
  • It penalizes larger errors more heavily, making it sensitive to extreme mispredictions (outliers).
  • Lower MSE indicates better performance.

2. Mean Absolute Error (MAE)

  • MAE calculates the average absolute difference between predictions and actual values.
  • Unlike MSE, it does not square the errors, meaning it treats all deviations linearly.
  • Since MAE is measured in pounds (same as BWEIGHT), it is easily interpretable as the model’s average prediction error in pounds.
  • Lower MAE means more accurate predictions on average.

3. R-Squared Score ( R^2 ) (Coefficient of Determination)

  • Measures how well the model explains the variance in birth weight.
  • A value of 1.0 means perfect predictions, while 0 means the model is no better than always predicting the mean birth weight.
  • It can be negative if the model performs worse than a naïve baseline (e.g., always predicting the mean).
  • Higher R^2 values indicate a better fit to the data.

Final Goal

The primary goal is to:

  • Minimize error (reduce MSE and MAE)
  • Maximize R^2 to ensure the model generalizes well

3. Evaluation Protocol¶

Given the large dataset (101,400 samples), we will use a hold-out validation approach for model evaluation:

  • We will split the data into training set, validation set and testing set.

    • Training set: 70980 (70%)
    • Validation set: 20280 (20%)
    • Test set: 10140 (10%)

This leaves a substantial number of examples for training while reserving a large set for unbiased evaluation.

  • Using hold-out validation is appropriate here because the dataset is large enough that we believe the hold-out portions are representative.

In summary, we will train on the training set, validate on a separate subset during development, and finally evaluate the chosen model once on the test set to report its performance.

4. Dataset¶

The Birth Weight Prediction Dataset contains 101,400 records, each representing a newborn and its associated maternal, paternal, and prenatal factors. The dataset includes 36 predictor variables and a target variable (BWEIGHT), which records the baby’s birth weight in pounds.

Key features encompass demographic information such as the mother’s and father’s age (MAGE, FAGE), education levels (MEDUC, FEDUC), race (RACEMOM, RACEDAD), and Hispanic origin (HISPMOM, HISPDAD).

It also includes pregnancy-related details such as weight gain during pregnancy (GAINED), number of prenatal visits (VISITS), total previous pregnancies (TOTALP), and gestational age in weeks (WEEKS).

Several features describe the mother’s health history, including conditions such as anemia (ANEMIA), cardiac disease (CARDIAC), diabetes (DIABETES), and hypertension (HYPERCH, HYPERPR), as well as lifestyle factors such as daily cigarette (CIGNUM) and alcohol consumption (DRINKNUM).

The dataset also tracks prior pregnancy outcomes, such as previous preterm births (PRETERM), history of large infants (PINFANT), and outcomes of previous deliveries (LOUTCOME).

5.2 Encoding Categorical Variables¶

Some categorical features need to be converted into numeric form for the machine learning models.

Categorical Columns Identified Multi-Class Categories (Require One-Hot Encoding)

  • RACEMOM, RACEDAD: Race Categories (0-9) = One-hot encode
  • HISPMOM, HISPDAD: Hispanic origin categories (C, M, N, O, P, S, U) = One-hot encode

We will drop one category for each one-hot coded varible (drop_first=True) in order to prevent redundancy and ensure independent feature learning, because:

1. Regression Models Assume Feature Independence

  • Since Mean Squared Error (MSE), Mean Absolute Error (MAE), and R-squared (R²) are sensitive to redundant features, dropping one category prevents multicollinearity, which can cause instability in training.

2. Neural Networks (Deep Learning) Perform Better Without Redundant Features

  • Unlike decision trees, deep learning models prefer independent input features for better optimization.
  • If all one-hot encoded categories are kept, the network might struggle to learn efficiently, leading to unstable weight updates.

5.3 Feature Scaling¶

In this step, we prepared the dataset for training by performing feature scaling to ensure all input variables contribute equally to the learning process. Neural networks are sensitive to input feature magnitudes, so standardization was applied to bring all numerical values onto a similar scale (i.e., manipulate into tensors).

  1. Feature Separation
  • We first separated the target variable (BWEIGHT) from the independent features.
  • The target variable was not scaled since it represents birth weight in pounds, which we want to predict in natural units.
  1. Standardization Using StandardScaler
  • We applied StandardScaler to transform numerical features using the formula:

X_scaled = [X-mean(X)]/std(X)

  • This process centered all features around 0 (mean ≈ 0) and scaled them to unit variance (std ≈ 1).

6. Develop a model that does better than a baseline¶

As we have a pretty large sample size, we will split the data up into:

  • 70% Training Set: Used for learning and adjusting model weights
  • 20% Validation Set: Used to tune hyperparameters and prevent overfitting
  • 10% Test Set: Used only once after training for final evaluation

As we are dealing with regression to arbitrary values (i.e., predicting weights in pounds):

  • There is no last-layer for our model because birth weight is a continuous value, not bounded between 0 and 1.
  • Loss function used in this case is Mean Squared Error (MSE)
  • Optimizer used will be Adam (had a trial with RMSprop initially but it did not perform as well as Adam)

6.1 The Plan¶

A. Baseline Model(Linear Regression)

We will compare the neural network to a simple linear regression model, if it can't outperform the linear regression, then either:

  • Our data is not informative enough, or
  • Our neural network architecture needs adjustments

B. Small Neural Network Model

  • Input Layer: Matches the number of features in X_train
  • Hidden Layers: 1-2 layers(small but expressive enough)
  • Activation Function: ReLU for hidden layers
  • Output Layer: Single neuron, no activation function (raw numeric output)
  • Loss Function: MSE
  • Adam

C. Evaluation Metrics

  • Mean Absolute Error (MAE)
  • Mean Squared Error (MSE)
  • R-squared score (to compare with baseline)

Data Splitting:

Tensor Conversion

Model Building & Training

  • A shallow neural network is built using the Adam optimiser.
  • Early stopping is applied to halt training if validation loss does not improve for 5 consecutive epochs.

Evaluation

  • The model is evaluated on the validation set only, leaving the test set for the final evaluation after model seletion.

Visualisation

def build_dropout_l2_model():
    model = keras.Sequential([
        keras.Input(shape=(X_train_tensor.shape[1],)),  # Explicit input layer
        layers.Dense(128, activation="relu", kernel_regularizer=l2(0.01)),
        layers.Dropout(0.3),  # Dropout after first hidden layer
        layers.Dense(64, activation="relu", kernel_regularizer=l2(0.01)),
        layers.Dropout(0.3),  # Dropout after second hidden layer
        layers.Dense(32, activation="relu", kernel_regularizer=l2(0.01)),
        layers.Dropout(0.3),  # Dropout after third hidden layer
        layers.Dense(16, activation="relu", kernel_regularizer=l2(0.01)),
        layers.Dropout(0.3),  # Dropout after fourth hidden layer
        layers.Dense(1)  # Output layer (regression)
    ])
    model.compile(optimizer=keras.optimizers.Adam(learning_rate=0.001),
                  loss="mse",
                  metrics=["mae"])

10. Analysis and Conclusion¶

The results demonstrate the progression from a simple baseline model to increasingly sophisticated neural network architectures, highlighting the effects of overfitting, regularization, and tuning techniques.

Baseline vs. Neural Network Performance

The baseline model, which simply predicts the mean birth weight, performed poorly with an MAE of 0.9697 and an R² score of -0.0007, meaning it captured almost no variance in the data. However, introducing a shallow neural network with Adam optimization and early stopping significantly improved performance, reducing MAE to 0.8528 and increasing R² to 0.3121. This confirms that neural networks are capable of learning meaningful patterns in the data.

Overfitting Model

A more complex model with more layers and neurons led to extreme overfitting. The MAE skyrocketed to 4.1005, MSE increased to 34.5941, and R² dropped drastically to -18.7768, indicating that the model had memorized the training data but failed to generalize to the validation set. This result emphasizes the need for regularization and proper architecture tuning to balance optimization and generalization.

The Effect of Dropout Regularization

To combat overfitting, dropout layers were introduced, which improved generalization. The MAE decreased from 0.8528 to 0.8137, and the R² score improved to 0.3761. This confirmed that dropout effectively prevents excessive reliance on specific neurons, promoting a more distributed representation of features.

Combining Dropout with L2 Regularization

Adding L2 weight decay alongside dropout provided a small improvement, reducing MSE from 1.0913 to 1.0833 and slightly increasing R² to 0.3779. While the difference was minimal, it suggests that L2 regularization contributes to stabilizing weights and improving generalization, though its impact alone was not drastic.

Testing Deeper Networks and Batch Size Adjustments

Increasing the depth of the network by adding more layers resulted in slightly worse performance, with R² decreasing to 0.3579, suggesting that simply making the model deeper does not necessarily improve performance. On the other hand, increasing the batch size to 256 performed almost identically to the best dropout model, indicating that batch size adjustments alone do not always yield major improvements.

Conclusion¶

The best performing model so far is the Dropout + L2 Regularization Model, which achieved the lowest MAE (0.8133) and the highest R² score (0.3779). This confirms that regularization techniques like dropout and L2 weight decay help prevent overfitting and enhance generalization.

Future Work¶

Moving forward, we can explore Bayesian Optimization to fine-tune hyperparameters such as learning rate, dropout rate, and batch size. Additionally, experimenting with alternative activation functions (such as Swish or LeakyReLU) and trying L1 Regularization (or ElasticNet, which combines L1 and L2) could further improve the model’s predictive power.
